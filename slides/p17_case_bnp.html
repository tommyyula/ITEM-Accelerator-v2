2.4 BNP → Dynamic Form → PEI

证明建模资产可以从业务对象与规则迁移到可运行表单，再扩展到复杂业务生态，而不是停留在聊天入口。

Demo 视频 · 待接入 16:9 视频区 · 待接入素材

迁移链

BNP 业务对象与规则 → Ontology Studio → Agent Factory 配置能力 → ITEMGPT Runtime 表单页面 → PEI 伙伴、采购或生态流程。

观看检查点

1. BNP 的对象、规则和边界是否先被明确？
2. Ontology 如何转成表单字段与 Action？
3. 迁移到 PEI 时，哪些共用、哪些差异化？
4. 是否呈现了治理与复用，而非只生成页面？

建模输入

业务对象、状态、规则；BNP 全称与范围待 Owner 补充。

能力配置

Agent、Ontology、Skill、Tools 组合；不假设已有成熟度。

应用运行

Dynamic Form 承接现场任务；权限与写回边界待确认。

生态扩展

PEI 伙伴/采购/生态范围待确认，先做工作坊推演。

证明任务

同一套业务理解能否在相关流程中迁移，是本例的验收核心；BNP 与 PEI 的正式全称、负责人和可演示边界不在本页猜测。

讨论 / 产出 哪些对象与 Action 应标准化？产出 BNP/PEI 的共用项、差异项与待确认 Owner。 17 / 40
