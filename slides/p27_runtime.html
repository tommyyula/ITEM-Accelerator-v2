4.1 ITEMGPT Runtime：目标表达、标准化、后台执行

Runtime 的价值不是一个聊天入口，而是把业务目标翻译成可复用、可控、可反馈的工作流。

01 / 目标

用业务语言提出任务

例如：生成 WMS 异常表单、解释 BO 原因与 ETA、整理 CEC 记录为 SOP 草稿、提出料件替换建议。

02 / 标准化

套用组织约定

模板、标准字段、业务术语、标准输出格式和质量检查，把个人定制变成组织可读的输入。

03 / Action

按权限给出下一步

查询、建议与写入分层；低风险动作可自动执行，高风险动作保留业务确认，具体等级待确认。

04 / 回流

让后台任务持续运行

状态监控、资料整理、任务派发、通知、同步和异常提醒由 Robotics 机制承接，异常回到人。

四个入口，保持同一条标准

业务请求Runtime 应追问或校验
WMS 异常表单订单、料件、位置、异常、照片；确认写回 WMS 的权限与字段。
BO 原因与 ETA事实来源、时间戳、风险解释；不要把建议当成 Customer Promise。
CEC SOP 草稿记录上下文、动作、结果；业务 Owner 审核后再发布。
料件替换建议库存、优先级与运输约束；高风险 Action 需人工确认。

后台效率，不等于自动承诺

  • 小模型：高频分类和路由
  • 规则/模板：稳定流程
  • 大模型：复杂理解与解释
  • Ontology：压缩上下文、限定范围
  • 缓存：重复任务复用
  • 人工：异常与风险升级

以上是建议的分工框架，不代表现有 Runtime 已具备全部能力；Token Saving 需以真实调用与质量口径验证。

操作边界

本页是概念操作流程，不是产品截图或已上线界面。 现场可任选一个业务请求，填入输入、标准、Action 权限、质量检查和反馈Owner，形成可讨论的 Runtime 验收草案。
