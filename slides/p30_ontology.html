5. Ontology Studio：从知识挖掘开始的第一环

先把事实、事理与行动组织成统一业务语义，再让 Data、Model、Agent、Dynamic Form 与 Action 进入同一条可治理链路。

01

挖掘事实

识别业务对象、状态与数据来源。Ontology 让 Data Hub 不止是连接。

→
02

定义事理

表达关系、规则、例外和优先级。Model Hub 不再只是模型集合。

→
03

约束行动

明确可自动执行与须人工确认的 Action，形成版本、测试和反馈闭环。

为什么是第一环

没有统一语义，Agent 只能依赖个人 Prompt，Dynamic Form 只能生成页面，Action 也难以判断边界。

本章结论：Ontology 不是名词清单，而是业务知识到可执行流程的共同起点。

共建不等于单方录入

业务 Owner 讲目标与例外；DT / Senior User 梳理系统关系；FDE 补充现场规则；Item 负责方法、工具与产品化；IT / Security 确认权限和生产要求。

角色边界与 Owner 仍需在工作坊现场确认。

本章产出

一张可讨论的初版业务模型范围：对象、关系、规则、Action、数据来源、风险等级、Owner 与版本反馈入口。以 BO / Customer Promise 为工作坊推演主线，不声称已有完整模型。

讨论/产出 哪个业务对象最需要先统一语义？现场形成“首批 Ontology 范围 + 角色分工 + 下一验证门”。30 / 40
