5.2–5.3 现场共建一张可执行业务模型

每个首批 Hero Cases 小组只提交一张可审阅的初版范围：先说业务目标，再落到对象、规则、Action 与责任边界。

00–05 分钟

目标与对象

写清业务目标、客户承诺、关键对象和必须保留的例外。

05–10 分钟

关系与规则

画出状态变化、影响链、优先级、替换、库存与运输规则。

10–15 分钟

Action 与数据

区分自动、审批、只读；标出数据来源、更新时间和缺口。

15–20 分钟

版本与发布

登记缺失、Owner、版本反馈与下一决策门，不虚构已完成模型。

业务 Owner谁解释目标、流程、例外与价值口径？待确认
DT / Senior User谁梳理系统、流程和字段关系？待确认
FDE / Item / IT Security现场规则、方法产品化、权限生产边界；待确认
小组填报字段必须写清未确定时
对象—关系—规则对象定义、状态、影响方向、数据来源与例外标“待确认”，记录需要访谈的团队
Action 风险只读 / 通知 / 状态同步 / 替换 / 承诺变更不把模拟动作写成真实执行
产出与下一门初版范围、Owner、证据、时间边界、发布门没有数据就列口径，不写数字或 ROI

本轮产出：一页初版 Ontology 范围 + 缺失项清单 + Action 风险分级 + Owner/输入/产出/下一决策门。该成果用于后续沙盒测试与版本讨论，不代表生产就绪。
