MD §6.2–6.5 联合交付工作页 · 建议 15 分钟

6.2–6.5 先理解业务，再共建、训练

四阶段把“想做 Agent”变成可检查的输入、产出和决策门；时间、Owner 与成熟度现场确定，不把建议写成既成状态。

四阶段交付路线

01

知识挖掘

输入：CEC、eSVC、UKM、SSC/GPO、Global Logistics、Field Service访谈与现有资产。

产出：Business Knowledge Map、Process Breakpoint Map、Hero Cases 优先级、初版 Ontology。

02

能力基座准备

输入：数据源、UKM / EKP / EKF、接口、算力、模型、Connector、Tools。

产出：Capability Inventory、Catalog、安全与上线要求、POC 环境。

03

典型 Agent 共建

输入：优先 Hero Cases，先 BO / Customer Promise，再知识、CEC、WMS 等组合。

产出：少量端到端闭环、沙盒证据、风险分级与待补能力。

04

Training 与普及

输入：标准 Agent、Runtime、Factory、Ontology 与反馈机制。

产出：业务用户训练；DT / FDE / Senior User 的构建、Qualification、发布训练。

每阶段的决策门

门 1 · 价值与边界

是否有业务 Owner、可验证问题、数据边界与不做事项？

门 2 · 能力可用性

Data / Model / Connector / Tool / Action / 权限是否有责任人？

门 3 · 风险与证据

关键规则、异常、人工接管、日志与脱敏测试能否复盘？

门 4 · 采用与复用

用户训练、反馈入口、版本维护和跨场景复用条件是否成立？

现场填写 · Owner

业务 / 技术 / 产品 / 安全

每阶段至少一名业务 Owner 与技术 Owner，具体人选待确认。

输入 → 产出

证据而非口号

将数据目录、沙盒记录、测试集、训练签到或反馈日志作为证据。
