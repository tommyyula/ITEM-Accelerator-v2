2.5 Record & Reply → CEC SOP

把一次交互中的问题、上下文、动作与结果，转成可审核、可发布、可复用的组织知识。

▷
Demo 视频 · 待接入 16:9 视频区 · 待接入素材

知识沉淀链

交互导入 → 提取问题、上下文、动作和结果 → 对比 SOP → 标记缺失 → 形成结构化草稿 → 业务 Owner 审核 → UKM / Ontology / Skill 发布。

观看检查点

1. 交互内容是否被拆成可审核事实？
2. SOP 缺失或不一致如何标记？
3. Owner 审核前后有哪些版本证据？
4. CEC/Genesys 下一次调用如何反馈修正？

提取

问题、上下文、处理动作、结果与不确定项。

比对

对照现有 CEC SOP，标出缺失、冲突和需补证据之处。

发布

业务 Owner 审核后进入 UKM、Ontology 或 Skill；版本边界待定。

回流

使用反馈优化知识；不把一次生成写成自动上线。

待决策边界

“不存视频”要求、Edge server 部署绑定与数据留存边界必须单独确认；本页不声称已有实现，也不虚构视频或部署状态。
