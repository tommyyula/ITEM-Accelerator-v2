1.2 判断能力必须分工

同一个业务任务需要多种判断：大模型理解与解释，预测模型估计未来，优化模型在约束中求解，Ontology 负责可控边界。

A · SCENE MODELING

场景建模

先把业务事件、时序、网络和生命周期结构化，让后续判断有稳定上下文。

场景聚合 · 时序结构化 · 物流网络拓扑 · 产品/设备生命周期
B · DECISION SUPPORT

决策支持

输出 ETA、需求、产能或风险的预测，并给出置信与原因，供业务选择。

Le-TSFM · Router-based Hybrid Forecast · 层级预测 · 预测解释
C · OPTIMIZATION DECISION

优化决策

把库存、运输、优先级和资源等约束放入方案比较，产生可审议的取舍。

Le-OPT · 多目标优化 · 料件替换 · 路径/装箱/库存优化
任务级协同，不是算法堆叠
业务问题
Ontology / 规则
限定对象、状态、可用动作
预测 / 优化
分别回答“会怎样 / 怎么选”
LLM / Agent
理解请求、解释方案、编排流程

一条 BO 判断链

订单与物流事实 → ETA / 风险预测 → 替换、库存、运输方案 → Agent 用业务语言解释。

小模型放在哪里

高频分类、路由或稳定任务可由小模型与规则承担；具体目标和正式模型名待确认。

模型名称的边界

Le-TSFM、Router-based Hybrid Forecast、Le-OPT 等沿用原材料写法；正式英文、成熟度与可用范围需 Owner 确认。
